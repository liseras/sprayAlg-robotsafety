## 1. 三条硬要求怎么落地的

### 1.1 内壁法向非朝上 → 加倾斜角

判据写在 `planner._need_tilt`：

| 面 | 判据 | 基准倾角 `tilt0` |
|---|---|---|
| 朝上的面 | `n_z ≥ cos(45°)` | **0°**（垂直喷，工艺最优） |
| 侧壁 / 内壁 | `n_z < cos(45°)` | **20°**（`--tilt-nonup`） |
| 朝下的悬垂面 | `n_z < −0.7` | **0°**（往上扳会顶穿工件，所以不扳） |

`tilt0` 只是**起点**，不是结论。起点下若间隙不够或够不着，按 5° 步进加大到 `--tilt-max`（默认 60°）；
还不行就把"往上扳"的方位左右偏 30°/60° 再试（内壁往上扳常常会顶到对面的壁）。

**为什么倾斜轴要"指向上方"**：这是唯一能把枪身从内壁里"翻出来"、同时又不改变末端到面点距离的方向
（见 1.2）。轴 = `up` 在法向切平面上的投影，法向与竖直夹角 < 5° 时无切向可扳，直接不倾斜。

### 1.2 倾角改变，但 TCP 到面点的距离不变

这一条是整个模块的几何地基，写死在 `planner.Evaluator.eval_pose` 里：

```
d(θ) = Rot(axis, θ) · n              # 枪身朝外方向，轴在 n 的切平面内
TCP  = face + standoff · d(θ)        # face 是**原始面点**，不随倾斜移动
⇒ |TCP − face| ≡ standoff            恒等式，不是近似
```

即 TCP 是**绕面点做球面旋转**，不是平移。所以：

* 变的只有喷角 θ（= 枪轴与法向夹角）；
* 喷距一分不变，**逐点实测** `standoff_err = ||TCP−face| − standoff|` 并写进报告的"喷距保持最大偏差"。

实测：所有样本 `standoff_max_err = 0.000000 mm`（浮点级）；FK 反算 TCP 与写回 CSV 的坐标差 0.05mm。

> ⚠ **踩过的坑（最严重的一个）**：工具坐标系 `+Z` 必须取 **−n**（= 喷射方向，指向工件），
> 一度取成 `+n`。症状极具迷惑性：位置全对、喷距也守恒，但 IK 只能选出"反腕 + 大臂下探"的解
> （θ2=154°、J2 超限 19°、J5-J6 连杆穿工件 24.7mm）。修正后同一批点从"全超限"变成余量 +46°。
> 这个错误还连累过一个**错误的 L0 结论**："tool_len(150) > standoff(100) ⇒ 法兰陷进工件"。
> 真相反：工具越长法兰离工件越远、越安全。`precheck` 里留了记录。

### 1.3 碰撞：轨迹 vs 工件、连杆 vs 连杆

| 项 | 口径 |
|---|---|
| 碰撞体 | 底座(可选)/J1..J6 关节球/6 根连杆/工具握把/细管/喷嘴，**全部按胶囊**（A-B 轴 + 半径 R） |
| 表面距离 | 点到轴最短距离 − R，**< 0 即穿透** |
| 半径来源 | `ArmSizing.From`：`jointR=clamp(reach·0.038,12,46)=34.39`、`Joint1R=42.99`、`LinkR=21.32`、`WristLinkR=24.76`、`GripR=21.32`、`ToolPipeR=9.59`、`NozzleR=6.39`、`BaseColumnR=89.4`、`BaseNeckR=39.5` |
| 判定带 | `--search`（默认 120mm，与 `CloudCheck.EffectiveSearchMm = max(120, safety·4)` 同口径）。带外**只报下界**，绝不当实测值 |
| 自碰撞 | 非相邻连杆胶囊两两最小距离 − 半径和（Ericson 5.1.9 解析解，0.015ms/次，无采样误差） |
| 连杆表 | 官方 `vs087.urdf`：J1(0,0,197.5)+Z±170 / J2(30,0,197.5)+Y−100~135 / J3(0,0,445)+Y−133~150 / J4(−20,0,287)+Z±270 / J5(0,0,143)+Y±120 / J6(0,0,80)+Z±360；reach 905；工具 150mm |

**FK 口径**与 `DensoArmKine/Kinematics/FkSolver.cs` 一致：`T_i = T_{i−1}·Trans(offset)·Rot(axis, θ)`，
转轴取 `R_{i−1}·axis`。

## 2. 最重要的一个发现：倾角和间隙不是单调关系

倾角和间隙**不是单调关系**。在凹槽/内壁里，倾角越大、喷嘴反而越往死角里扎：

```
complex 样本 idx 3163 的实测曲线（同一面点，只改倾角）
  tilt   0°    5°   10°   15°   20°   25°   30°   35°   40°   45°   50°   55°   60°
  clear 14.2  13.8  14.8  17.1  18.3  17.9  14.7  10.5   7.5   5.6   1.8  -2.4  -2.0   (mm)
```

这条曲线否掉了「倾角越大越安全」这个隐含假设。它也说明：只要倾角还是**逐点自由量**，
就一定会有某个点为了自己的间隙单独把倾角抬上去，整面姿态随之漂移。

### 2.1 姿态是「面级常量」，不是逐点自由量

早期做法是「逐点求最小可行倾角 + 只升不降的限幅平滑（每点 ≤3°）」。限幅平滑能保证
`|Δθ| ≤ 3°`，但保证不了**同一个面上倾角不变**——开口盒子实测一笔 77 点里倾角
`30° → 55° → 30°`，因为每个点都在为自己的间隙单独讨价还价。

倾角不是无关紧要的小角度。它是绕表面点做的**球面旋转**，TCP 位移 `2·standoff·sin(θ/2)`：
`standoff=100mm` 时 30°→52mm、60°→100mm。相邻两点方位再翻 180°（同倾角、一上一下），
两个 TCP 相差 `2×100×sin60° = 173mm` —— 界面上是"长刺"，实机上是一次甩腕。

现在的做法：把法向一致（夹角 ≤2°）、共面（沿法向偏移 ≤2mm）的相邻行归成一个**面组**，
一个面组只允许一个 `(倾角, 方位)`。姿态只可能在换面时改变，面内逐点恒定。

面组姿态用**抽样打分择优**，且所有候选必须在同一采样数下比较（否则会挑出"只在小样本上
好看"的姿态）。比较次序：

| 档 | 判据 |
|---|---|
| 1 | P0 点数 = 枪体/连杆穿透 + IK 不可达 + 自碰撞，带 `2%×抽样 + 2 点` 容忍带 |
| 2 | 工艺喷角 ≤ `max_spray_angle_deg`（默认 30°） |
| 3 | 间隙不足点数 `short_clr` |
| 4 | P0 点数（精确比，出了容忍带再分胜负） |
| 5 | 倾角更小 → 方位更趋 0 |

采样分三段：`16 点`粗筛 → 容忍带 partition → `96 点`复核 → 仍有 P0 则 `400 点`定档。

**打分必须用热种子链**。阶段 3 的 IK 是接着上一点继续解的；打分如果每次都冷启动（全零种子），
本来够得着的点会被判成不可达。开口盒子 +X 内壁整面 2104 点就是这么被判死的：9 个候选全是
「冷启动 400/400 不可达」，选优只能退回「倾角最小」，整面 30° 一个都解不出。改成热种子链后
IK_FAIL 2104→**133**、可达 89.0%→**99.3%**、P0 2596→**864**（比改动前的 1302 还低）。

**代价必须讲清**：一个面组只有一个姿态，几何上"整面没有共同可行姿态"时就必然有牺牲。
开口盒子 9 个面组里，+X 内壁那 2104 点无论选哪个候选都有点够不着；现在靠热种子打分 + IK 救援
把不可达压到 133 点，剩下的照实记 `IK_FAIL`，不藏起来。该件最终仍是 `REJECT`，但原因是
连杆物理穿透（LINK_HIT 539 / TOOL_HIT 102，最小 −21.2mm），不是姿态 —— 见第 6 节基座假设。

### 2.2 回退只受硬约束限制

面级姿态过不了硬约束的点，逐点回退；但**只在硬约束被破坏时才回退**，不是"间隙比本点
最优小几毫米就回退"。

硬约束 = IK 成功 + 不自碰撞 + `clearance ≥ hard_clearance`（默认 2mm）+ 关节不超限。
回退优先**最小偏离**：先试 `±1×tilt_step`，不行再 `±2`、`±3`，避免为 1 个点把整段姿态
甩出去。回退点记 `reverted`，CSV 的 `tilt_jump_deg` 列可见。
`safety`（默认 20mm）只负责 P1 标橙告警，不是回退阈值。

历史成绩（`complex` 由"严格回退"改到"只回退硬约束"）：

| | 修复前 | 只回退硬约束后 |
|---|---|---|
| 结论 | REJECT | **P0 = 0** |
| 最小表面距离 | −5.81 mm（穿透） | **+19.87 mm** |
| COLLISION 点数 | 6 | **0** |
| CLEARANCE 点数 | 58 | **2**（19.87 / 19.99，就卡在 20mm 线上） |
| 回退点 | — | 114 |

取舍原则：**硬约束（碰撞/自碰撞/关节超限）永远压过姿态连续；硬约束通过时以面级常量为主**。

**最后一道闸：退回逐点最优时不许翻方位。** 阶段 3 原来在「面级姿态 + ±3 步倾角」都过不了
硬约束时，会退回阶段 1 逐点自搜的缓存位姿。那个缓存是**每个点自己搜出来的**，方位可能是
60°、面级是 0° —— 倾角看着只差 5°，TCP 却绕面点转了大半圈。

以开口盒子 idx 7070 为例（面级 `(60°, 0°)`、缓存 `(55°, 60°)`）：

| | 面级 (60°, 0°) | 缓存 (55°, 60°) |
|---|---|---|
| clearance | 0.89 mm | 0.93 mm |
| 相邻点 TCP 位移 | 8.7 mm（只差 5° 倾角） | **83.1 mm**（实测） |
| 硬约束 | 不过（`self_gap −0.38`） | **也不过** |

两个都过不了硬约束，退回只是把"撞"换成"另一种撞"，代价却是 83mm 的甩腕。所以现在：

1. 先试**面级方位 + 该点最优倾角** —— 方位不变，位移只有倾角那一点；
2. 缓存原样退回**只认方位相同的**，且必须真过得了硬约束（`hardOk`）；
3. 都不成立就**保持面级姿态**，违规照实报（间隙不足 / 自碰撞），由站位与基座去解决。

代价是 P0 变多（开口盒子 864→1113），但那些点本来就在撞，只是以前撞在别处、还顺带甩了腕；
`TILT_JUMP` 同时从 182 降到 **60**。

**IK 失败也要救一次**。面级姿态在个别点解不出逆解时，阶段 3 原来直接判 `IK_FAIL`；现在先按
「同方位、倾角 ±1/2/3 步」试一遍，过硬约束就用（记 `reverted`）。`longwide` 单层 12476 点
正是这种情况：面级 10° 下有 15 点解不出、20° 下全好，而 `15/12476 = 0.12%` 在 400 点抽样里
的期望命中只有 0.5 个 —— 抽样永远看不见，只能在逐点解时救。加上这道救援 `longwide` 的
P0 从 15 回到 **0**（可达率 99.9%→100%）。

回退还有最后一道：**回退段统一**（只做在 C++ 生产路径里，Python 参考实现未移植）。逐点回退
仍会在同一面上造出阶梯 —— 开口盒子 1417 个回退点落在 81 段里，其中 18 段在十几个点内连着
`30°→40°→55°→30°`。所以把相邻回退点（允许夹 ≤2 个非回退点、不跨行）归成一段，段内只用
一个姿态：候选 = 段内用过的姿态 + 面级姿态，容忍带 `2% 段长 + 1 点`（超出的那几个点保留
自己的位姿）。实测 `cao` 倾角行内步进 5.0°→**0.0°**、TCP 突跳 1→**0**；开口盒子回退段里的
**倾角台阶段**从 63 段降到 **37** 段，剩下的大多是回退段边界（物理上必须偏，躲不掉）。

> 29.2°，Python 是 2.7° / 19.5° —— 两者都满足面内恒定、都在 30° 工艺喷角内。比对时只看
> **「姿态是不是面级常量」**，不要逐点比倾角数值。

### 2.4 工具滚转（J6）的坐标系混用（2026-10-22 修复）

枪是回转体，绕枪轴滚转不改喷涂，但机器人会真的转。为了"滚转最小变化"，`eval_pose()`
拿上一点的工具 x 轴 `ref_x` 投影到新切平面 —— 这里 `ref_x` 来自 `fk()`，是**基座系**，
而 `z_tool` 是**点云系**。混着用等于每步多偏转一份「基座偏航」并逐点累加：

| 样本 | 自动基座偏航 | 修复前（喷涂段内关节步长） | 修复后 |
|---|---|---|---|
| `tray` / `panel` / `synth` | 0° | 0.50~0.54° | 0.50~0.54°（不变） |
| `complex` | 18.08° | **17.11°** | **0.47°** |
| `curved` | 非 0 | **178.55°** | **0.69°** |

判据很好用：**看哪些样本正常**——基座偏航为 0 的样本完全正常，正是坐标系混用的证据。
修法是投影前先 `to_cloud_R(ref_x)`。Python 与 C++ 两份实现都已修。

## 5. 已经验证到什么程度

### 5.1 运动学自检

* 60 组随机姿态 IK→FK 闭环：`worst_pos = 0.0053 mm`、`worst_rot = 0.0006°`；
* 连续 200 点圆弧：`mean 1.70ms / p95 2.89ms`，接近 100% 收敛；
* 加速手段（上一点解做种子 → 解析种子 → 固定种子表）**不得牺牲正确性**：
  只采纳"收敛 + 残差好 + 不超限"的解，否则继续试下一个种子。

## 6. 已知边界（必须知道的 7 件事）

1. **坐标闭环（P0）尚未完成**。点云系 → 基座系必须来自手眼标定或工位图纸。
   没给 `--base-pose/--base-json` 时，本层按"工件质心落在基座系 `(0.50·reach, 0, 0.35·reach)` ≈
   `(452, 0, 317)`、+X 指向工件"猜一个基座，并在报告里显式标注。
   **「可达率」与「连杆碰撞」结论依赖这个假设；枪体碰撞与喷距/喷角结论不依赖它。**
   实测手眼矩阵 `handeye_real_20260911.json`（绕 Z 转 32°、平移 (520,−180,940)）与点云 AABB
   （synth z 1127~1142、panel z 1343~1374）不自洽，说明轨迹坐标其实已在基座系 ——
   这个矛盾需要你确认后才能真正闭环。
2. **喷角上限 30° 是占位假设**。`ROBOT_SAFETY_交接说明` §提问清单明确把"喷角上限"列为待你拍板项。
   报告里会把"为保安全间隙需要的喷角分布"和这个假设上限并列，冲突点数一语道破，改 `--max-spray-angle` 即可。
3. **不含外部轴 / 变位机 / 导轨**。基座按固定安装处理。
4. **点云抽稀影响精度**。默认 `--max-points 25000`（按采样密度自适应体素）。抽稀会略降精度，
   要更高置信度就把 `--max-points` 调大（代价是线性变慢）。
5. **碰撞体是胶囊近似**，不含气管走向、夹具、料架、围栏。`--include-base` 只在点云含地面/底座时开。
6. **一个面组只能有一个姿态，这是刻意的取舍**。换来的是一面之内喷角绝对恒定（`行内倾角步进 = 0°`），
   代价是几何上"整面没有共同可行姿态"时必然有牺牲：开口盒子 face2 的 400 点、`longstripe`
   整面被抬到 59.1°。面组划分阈值（法向 ≤2°、共面 ≤2mm）在 `robot_safety.cpp` 里是常量
   `kSameFaceCos / kSameFacePlaneMm`；把面切得更碎能多救点，但会多出换面处的姿态跳变。
7. **界面用的是 bin 目录里的那份 `SprayTraj.dll`，不是构建目录里的**。改完 C++ 后必须
   `dotnet build -c Release`（PostBuild 会自动拷贝），或手动 `cp` 过去；**界面开着时文件被占用，
   PostBuild 拷贝会静默失败**。踩过一次：C++ 改完两轮，界面还在跑 10-22 的库，看到的数字
   （不可达 722 / 回退 2878）和新库（133 / 1299）完全对不上，而画面自然是旧的。
   现在结论卡最后一行会打印 `算法库：Oct 23 2026 13:22:33`（C ABI `robot_safety_build_stamp()`），
   对着它就能确认跑的是哪一版；没有这一行 = 旧库。

## 8. 留给下一个人的坑位提示

* `geom.tilt_axis_and_dir` 的退化判据**必须在归一化之前**取 `|u| = sin∠(n, up)`。
  先 `unit()` 再比阈值恒成立 → 平整朝上的面会被判成"非朝上"，喷角被加到 40°，
  而喷距仍然守恒、数字"看着正常"，极难发现。默认阈值 5°。
* 归一化雅可比条件数才有意义（位置行 / 500mm）→ 正常姿态 ~30；原始雅可比天然上千，
  正常姿态就 1118，拿它当奇异判据会误报一片。
* `search` 必须 ≥ `standoff`，否则所有段都饱和、报告里只剩"≥N"。
* 点云抽稀要按**采样密度**定体素（`s' = s·√(N/target)`），按 AABB 对角线会把 111k 点抽成 190 点。
* 报告里的表如果按逐点展开，几百行会淹掉结论 —— 违规一律按连续区段聚合，逐点清单留在 `verdict.json`。
