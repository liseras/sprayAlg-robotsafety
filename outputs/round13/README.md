# 第十三轮：重建曲面正则化 + 跨行姿态一致化

用户反馈：**"曲型板工件轨迹太烂，1.轨迹不平滑不规则，弯弯绕绕，2 轨迹之间还有相互缠绕。
是否说明重建的曲面不规则，不平滑，曲率不一致"**

## 结论：用户的判断是对的，但根因有两层

| 层 | 实测（改前） | 判定 |
|---|---|---|
| 重建网格 | 相邻三角面二面角 p50 **4.0°** p95 **26.0°** max **84.9°**；相邻顶点法向 p95 **36.4°** | **确实不平滑**（真实拱面 18mm 格距只该转 2.6°） |
| 贴面行位置 | 14 行在 (t,s) 域横向漂移 **0.5~3.0mm**，间距 11.76mm | 干净，不是乱源 |
| 枪位（面点+100mm·n） | 横摆 **37~105mm**；偏离行内平滑基准 p95 **17.6** max **39.0mm** | **这是"缠绕"的来源** |
| 相邻行枪位 | 横向反序率 **14%** | 视觉交叉 |

两件事必须先说清楚：

1. **查看器里的红线是枪位**（`面点 + standoff·n`），不是贴面轨迹。法向偏 1° → 枪头横移 1.75mm；
   行距只有 11.76mm，法向误差超过 6.7° 相邻行就互穿。
2. 逐点 PCA 法向是**重尾**分布：p50 误差 0.65°、p90 6.7°、**p95 17.2°、max 47.7°**
   （坏点集中在扫描条纹间隙与边缘外推处）。行内低通只在行内做，**跨行不一致它管不到**；
   6°/步限幅还会把单点异常摊成连续斜坡，形成可见"甩尾"（实测相邻点夹角 p95 恰好顶在 6.00°）。

## 改法：把"重建曲面"变成可求值/可求导的曲面模型，轨迹与姿态都从它导出

`SurfPatch` 新增重建曲面模型（与显示网格共用同一 (u,v) 参数域）：

| 字段 | 内容 | 用途 |
|---|---|---|
| `mH` | 格内中位高度 → 多值格(IQR>8mm)丢弃 → 归一化高斯 σ=1.5 格 | 显示网格顶点高度（曲率连续） |
| `mNm` | 格内逐点法向**取中位**（中位抗坏点）→ 3×3 归一化平滑 | 行点姿态的初值/兜底 |
| `mOcc` | 该格是否有实测点 | 几何可用扩散值、姿态只认实测格 |

链路改动：

1. `build_surf_model()`（新）：8.5mm 格（65×23=1495，占用 1017，多值格 112）。
2. `build_surface_mesh()`：格高改取模型高度，**并在网格自身尺度补一次 σ=1.2 格高斯** ——
   模型格比显示格细，只插值会留下格间台阶。
3. `gen_surface_rows()`：
   - 行点姿态查模型（`surf_model_query`）；
   - **跨行姿态场**：格宽取 `1.3×行距≈15mm`（必须大于行距，否则相邻行落不同格，
     跨行平均无从谈起），格内中位 → 4 遍 3×3 → 双线性插值回行点；
     四邻无行点时取 3×3 最近有效格（不能保留原噪声法向，那是枪位尖峰来源）；
   - 统一后**再过一遍行内低通+6°/步限幅**（格边界几度跳变会被 100mm 放大成 20+mm）；
   - 位置 `rowP` **一个点都不动**。
4. 行内平滑抽成 `smooth_row_normals(rn, passes, slewDeg)`，跑两遍。

### 为什么几何用平滑高度、姿态用中位法向

直接对平滑高度场求梯度会把残余噪声再放大一次：离线实测法向改动 p95 38°、
枪位反而从 17.6mm 恶化到 32mm；而"格内法向取中位再平滑"能把枪位压到 4.6mm。
两者共用同一网格，逻辑上仍是一个模型。

## 未收尾 / 风险

1. 网格二面角 p95 仍有 11.5°（理想 2.6°），残余集中在多值格(112 个)与空洞边界；
   再加大 σ 会牺牲真实曲率，需用户判断是否值得。
2. 端部仍有少量行被外推到点云之外（日志"投影后离点云 12~15mm"），那里的姿态靠最近有效格兜底。
3. `standoff` 仍按固定值抬升，姿态平滑后喷距波动变小，但端部真实折转（70~75°）依旧存在。
