# 第十四轮：纯多面体件不再被误判成曲面块

用户反馈：**"这个开口的盒子是怎么回事，都是非常完美的平面啊"**
（`开口盒子(模拟生成).ply` = `u06.ply`，34580 点，400×300×300 开口盒：底面 + 4 侧壁）

## 现象

| 指标 | 改前 |
|---|---|
| 判定 | **曲面块**（走等值线行追踪） |
| 轨迹 | 24 行 / 13424 点 |
| 覆盖率 | **57.3%** |
| 平面残差 `rms` | **59.55mm** |
| `seg_max` | 25.25mm（点距参数只有 4mm） |
| 观感 | 一团乱线：长斜线横穿、枪位四散、面之间来回跳 |

用户判断正确：这件的点云**极干净**——法向只有两簇（0~10° 有 7676 点、90~100° 有 26904 点，
中间完全为空），侧壁方位角精确落在 0/±90/180 四个方向。没有任何"曲面"可言。

## 根因：连通判据被棱边过渡点"架桥"

`detect_curved_patch()` 的第一步是并查集，按 **相邻点法向夹角 < 20°** 求最大连通块。

棱边两侧的点，KNN（K=25）邻域同时含两个面，法向落在 45° 附近的过渡带。
这一串过渡点把 0° 的底面与 90° 的侧壁**一段一段接起来**：

```
底面 0° ──过渡 20°──过渡 40°──过渡 60°── 侧壁 90°
```

于是 31215/34242 = **91.2%** 的点连成一个"光滑块"。这个块显然不共面
（整体平面拟合 p95 = **167.7mm**），而原判据只看"整体平面残差 ≥ max(4×curvatureTol, 2×行距)=24mm"
→ 直接判定为曲面。

> 换句话说：**"整体平面残差大"既可以因为它是曲面，也可以因为它是多面体。**
> 原判据只排除了后者以外的一切，对多面体毫无防御。

## 改法：能拆成几个精确平面的，就不是曲面

新增 `patch_is_polyhedral()`：块内做**紧公差顺序 RANSAC 剥离**，
若 ≤8 个平面就能覆盖 ≥93% 的点 → 多面体 → 退回 `split_planes` 平面分割。

- 公差 `tolPlane = clamp(0.2×行距, 1.5, 3.0)`，默认行距 11.76mm → **2.4mm**
  （既容得下现场点云的墙面噪声 ~0.5mm，又远小于"浅曲面被切成薄带"的厚度）
- 抽样到 ≤20000 点做判定（判的是覆盖比例，抽样不改变结论，但把成本压成常数）

### 分离度实测

| 工件 | 8 个平面在 2.4mm 公差下的覆盖率 | 判定 |
|---|---|---|
| 开口盒子 | 5 个平面即覆盖 **99.9%**（底面 23.2 / 长侧壁 22.3+22.3 / 端壁 16.0+16.0） | 多面体 ✅ |
| 曲型板 | 8 个平面只覆盖 **65.1%** | 曲面 ✅（连续曲面没有"平面带"可分） |

余量 35 个百分点，两边都不靠边。

> 为什么公差要跟着行距走：一个 sag 30mm 的缓曲面，在 3mm 带宽下只需 10 条带就能铺满，
> 固定大公差会把它误判成多面体。0.2×行距 时 8 个平面只够盖 ~75%。

## 风险 / 说明

1. 判据只对"已经越过曲面门限"的块生效，**不改变任何现在走平面路径的工件**（25/25 逐字节一致可证）。
2. **门限是标定值，不要凭感觉改**：现场 17 个点云里只有 u08（曲型板）和 u10（棕色槽型盘
   平滑重建）走曲面分支；u10 在 2.4mm 下 8 个平面已覆盖 **89.5%**，覆盖率门限一旦放到 90%
   就会把它翻成多面体。当前 93% 的三点标定：盒子 99.9% / 曲型板 65.1% / u10 89.5%。
3. 极端情况：一个 8 面体的件，若 8 个面加起来只覆盖 90%，会仍按曲面处理（保守）。
4. `ls.ply` 是二进制 PLY，驱动只吃 ascii，一直是读取失败，不算回归项；盒子样本已由
   `E:/tmp_build/userclouds/bin2ascii.py` 转成 ascii 并入库为 `cpp/_regress/box.ply`。
