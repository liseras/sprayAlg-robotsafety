# 为什么姿态会贴到限位：当前算法怎么定姿态，以及为什么"多解"救不了它

日期：2026-11-10　　机型：DENSO VS-087　　数据：`outputs/robot_safety_cpp/*/trajectory_checked.csv`（9 个算例）

---

## 0. 三句话结论

1. **方向解确实有多个（最多 16 支），但算法只取一支**，而排序里的"不限位"是**布尔值**——
   "全部在限位内"就算通过，不再比较还剩多少度余量。于是"余量 0.5°"和"余量 80°"同分。
2. **真正贴限位的是 J5**，而不是 J1/J2/J3。J5 的取值由**枪轴方向 ⊕ 前臂方向**唯一决定，
   一旦枪轴方向定死，θ5 就没有第二个值可选——换解支救不了。
3. **大平面上倾角被算法自己强制成 0**（朝上面 `tiltAxisAndDir` 退化），
   于是唯一能改 θ5 的杠杆被关掉。J5 想退都没得退。

## 1. 当前算法怎么算姿态（生产路径 `robot_safety.cpp`）

### 1.1 逆解：一个位姿最多 16+12 个种子，最后只留一支

`ik()`（`robot_safety.cpp:594`）的种子顺序：

```
上一点解（连续性） → analyticSeeds 最多 16 个（两连杆 2×2 × 腕部 ZYZ 2）
                  → kSeeds 12 个固定种子（兜底）
```

**关键在筛选规则**（`valid()`，`robot_safety.cpp:608`）：

```cpp
auto valid = [](const IkSol& s) {
    return s.ok && s.posErr < 0.05 && s.rotErrDeg < 0.05 && !s.over;
};
```

`!s.over` 是**布尔**：`over = 任一关节超出软限位`。所以：

- 只要有一支"全部在限位内"，哪怕 J5 只剩 **0.1°**，它就算合格，直接被返回；
- 排序 `rankCmp` 里"余量"只是**第 4、第 5 顺位**的 tie-breaker，且在 `valid` 之后才用到；
- 有 seed 时更极端：`maxJointDelta(sol, seed) <= 10°` 就**立刻 return**（`:623`），
  连另外 27 个种子都不跑。

### 1.2 姿态是三级作用域，从大到小

| 层级 | 作用域 | 代码位置 | 被谁锁死 |
|---|---|---|---|
| 面组级 `(tilt, az)` | 整个面组共用一个常量 | 阶段 2，`:2028` 起 | 大平面只有一个面组 |
| 行级 `az` | 一行共用一个方位 | `azRow`，`:2010` | 白名单 `kAzLimitDeg=60°` |
| 点级回退 | 只允许 ±1~±3 个 5° 步长 | `:2869` / `:2928` | 幅度被刻意限死（防甩腕） |

**"逐点连续"（bit1 `tiltPerPoint`）在大平面上等于没开**：
倾角只由该点法向决定（`tiltNeedDeg`，`:1370`），而大平面法向是常量 ⟹ 整面倾角相同。
这正是方案 C 文档第 1 节已经写到的结论。

## 2. 实测：哪个关节真的贴限位

按 CSV 里的 `J*_deg` 与 `kJoints`（`:318`）的 `lo/hi` 算余量：

| 算例 | 点数 | 最小余量 | J1 | J2 | J3 | J4 | **J5** | J6 |
|---|---|---|---|---|---|---|---|---|
| **big** | 9761 | **−5.2°** | 0.2 | 24.9 | 9.5 | 265.5 | **−5.2** | 206.6 |
| **longstripe** | 11558 | **−12.2°** | 20.2 | 42.1 | 7.1 | 25.2 | **−12.2** | 0.0 |
| cao | 1647 | 1.0 | 150.0 | 80.2 | 11.4 | 14.8 | **1.0** | 21.3 |
| complex | 4989 | 1.0 | 107.1 | 69.7 | 1.0 | 182.7 | 2.1 | 147.8 |
| curved | 3457 | 1.0 | 6.4 | 72.5 | 6.4 | 154.4 | **1.2** | 1.0 |
| longwide | 12246 | 8.0 | 99.4 | 49.8 | 12.1 | 85.3 | **8.0** | 21.9 |
| tray | 1323 | 7.6 | 119.6 | 90.7 | 24.4 | 211.0 | 7.6 | 251.0 |
| panel / synth | — | ≥17 | — | — | — | — | 57.3 / 53.8 | — |

**结论：瓶颈几乎总是 J5**（±120°）。J4/J6 是 ±270°/±360°，从来不是约束。
`big` 里 J1 的 0.2° 和 `longstripe` 里 J6 的 0.0° 都是**个别点**（3 个 / 1 个），属边角，
唯一成规模超限的是 J5（270 点 / 8 点）。

### 2.1 J5 到底由什么决定（实测验证，与方案 C 文档的公式不同）

方案 C 第 3 节写的是 `θ5 = arccos(d_z)`。**这个公式对不上数据。**
实测（`big` 最差点，枪轴 `g=(0.021,0.065,-0.998)`）：

```
|J5| 实测            = 125.2°
angle(前臂方向f, g)  = 125.2°   ← 吻合到 0.01°
arccos(g_z)         = 176.1°   ← 方案 C 的公式，差 51°
```

解析上也能证实：`R06 = Rz(θ1)·Ry(θ2+θ3)·Rz(θ4)·Ry(θ5)·Rz(θ6)`，
把 `u = R03ᵀ·g` 展开得 `u = (cosθ4·sinθ5, sinθ4·sinθ5, cosθ5)`，
所以 **|θ5| = arccos(u_z)**，其中 `R03 = Rz(θ1)·Ry(θ2+θ3)`。
θ5 是**枪轴在"前臂坐标系"里的倾角**，不是在世界系里对 z 轴的倾角。

对另外 4 个算例（big / cao / complex / tray）实测误差中位 **0.001°**、p99 **0.017°**，公式成立。

**这条修正是结论性的**：θ5 由「前臂方向」和「枪轴方向」共同决定，所以
**单靠改枪轴方向（tilt/az）能改 θ5，但单靠换 IK 解支不能**——
因为前臂方向本身也是被前三个关节定死的。

## 3. 为什么"多解"救不了：实测枚举全部解支

对最贴限位的点，用 28 个种子把全部解支都枚举出来，按余量排序：

### `big` 最差点（当前 margin = −5.23°）

```
找到 3 支：
  margin = −153.55°   J=[323.6, 94.2, −38.3, 4.5, 125.2, −303.8]
  margin = −114.77°   J=[−36.4, 94.2, −38.3, 4.5, −234.8, 56.2]
  margin =   −5.23°   J=[−36.4, 94.2, −38.3, 4.5, 125.2, 56.2]   ← 当前算法选的
```

**当前这一支已经是三支里最好的。** 另两支分别超 J1 和 J5 上百度和上百度——
它们是"J1+180°"这种把大臂绕一圈的等价解，物理上不可走。

### `longstripe` 最差点（当前 margin = −12.16°）

```
找到 6 支，最安全一支 margin = −93.94°：J=[−220.9, −46.9, −24.0, −5.2, 213.9, −119.9]
当前一支 margin = −12.16°  ← 仍然最好
```

### 全件抽样（big，400 点）

```
可取到的额外余量 Δ = 全支最优 − 当前：
  中位 = −0.00°   p90 = 0.01°   max = 49.45°
  Δ > 3° 的点数 = 4 / 400 (1.0%)
平均收敛解支数 = 19.5（真正互不相同的一般 3~6 支）
```

**结论：换解支在 99% 的点上换不出任何余量。**
"方向有多解"这句话在**位置**层面成立（肘上/肘下、肩前/肩后），
但在**腕部余量**层面不成立——因为 θ5 是枪轴方向的函数，而枪轴方向在面级常量下是定死的。

## 4. 真正的原因：唯一的杠杆被算法自己关掉了

### 4.1 朝上的大平面，倾角被强制为 0

`tiltAxisAndDir`（`:1351`）：

```cpp
V3 u = ref - n * dot(ref, n);
if (norm(u) < std::sin(5.0 * kDeg)) {   // 法向与基准夹角 < 5°
    axis = V3(0,0,0); uUp = V3(0,0,0); return;
}
```

无基座位姿时 `ref = upW = 重力 +Z`（`:1867`）。朝上的平面 `n ≈ +Z` ⟹ `|u| ≈ 0` ⟹ **退化**。
退化后 `needTilt` 里 `tilt0 = 0`、`cand` 只剩一个、`az` 也只有 0 一个值。

实测（`big`）：

```
枪轴与 −Z 夹角 中位 = 3.9°（整件几乎完全朝上）
倾斜轴退化率 = 100.0%  → 倾角被强制 0
tilt_deg 唯一值 = [0.]   非零点数 = 0 / 9761
```

**这就是"整面锁死一个姿态"的机制**，而且比方案 C 描述的更彻底：
方案 C 以为是"面组常量 + 法向恒定"，实际是**退化把倾角直接归零**，
连"整面共用一个非零倾角"都做不到。

对比 `longstripe`（法向偏 36°，不退化）：`tilt_deg` 有 34 个不同值，J5 仍有 270 点超限。
即**非退化面上倾角能用，但仍是面级常量，远端照样被近端绑住**。

### 4.2 方位被白名单和"行级单值"双重限制

- `kAzLimitDeg = 60°`（`:2243`）：只允许"上翻方向左右 60°"，超出直接 `return`；
- `azRow` 是**行级**单值（`:2010`）：一行两端共用一个方位。

### 4.3 绕枪轴滚转对 θ5 完全无效（这一条方案 C 说对了）

θ5 是滚转角的不变量，滚转只改 θ4/θ6 的分配。`big` 里 J4 最小余量 265°、J6 206°，
确实怎么滚都不会成为约束。**不要再往这个方向投入。**

所以三个杠杆的实际状态是：

| 杠杆 | 理论上能改 θ5？ | 大平面上的实际状态 |
|---|---|---|
| 倾角 tilt | ✅ 能 | ❌ 朝上面退化 → 恒 0 |
| 方位 az | ✅ 能 | ⚠️ 行级常量 + ±60° 封顶 |
| 绕枪轴滚转 | ❌ 不能 | — 不要做 |
| standoff | ✅ 能（改腕心位置） | 工艺量，不动 |
| 基座位姿 / 站位 | ✅ 能 | 换工作空间，需现场 |

## 5. 一个必须知道的副作用：J5 会突然从 +125° 翻到 −109°

`big` 前 8 点是 J5≈+122…+125（超限），**第 9 点直接跳到 −108.7**：

```
 #   J1     J2     J3    J4    J5     J6    margin
 7  −36.4   94.2  −38.3  4.5  125.2   56.2   −5.23   JOINT_LIMIT
 8  143.8  −75.1    2.7  3.9 −108.7 −125.0   11.35   NEAR_SINGULAR
```

ΔJ5 = 234°、ΔJ1 = 180°。这不是噪声，是**解支整体翻转**（肘上↔肘下 / 肩前↔肩后）：
算法在 #8 点发现原支过不了限位，退回"找最近合法解"，于是整条臂换了构型。
`longstripe` 里同样存在（相邻点最大关节步长中位 179.85°、全件 11514 个点对 >5°）——
那种件是"整条轨迹都在翻"，属于更严重的另一类问题。

**这一条比"贴限位"更危险**：贴限位是走不动，翻支是会在空中猛地甩一圈。

## 6. 怎么保证姿态不到限位（按优先级）

### P0 · 把"不限位"从布尔改成连续余量目标

现在的 `valid()` 只要 `!over` 就放行，`margin` 只做 tie-breaker。
应当改成：**余量不足 `jointMarginMin`（默认 1°，建议提到 10~15°）就不算合格**，
并且 `rankCmp` 里把余量提到"收敛"之后的第一顺位。

改动点：`robot_safety.cpp:608` 的 `valid()`、`:547` 的 `rankCmp`。
这不能救大平面（因为解支换不出余量），但能**立刻止住"余量 0.5° 也算通过"**这类假通过，
并且让 270 个超限点如实计入 `JOINT_LIMIT`。

### P0 · 修 `tiltAxisAndDir` 的退化口径

朝上的面上"倾斜"不是没有物理意义，只是**绕哪个轴扳**需要另给参考。
现在直接返回零向量等于放弃这个自由度。建议：
法向与基准夹角 < 5° 时，不退化，而是用**基座→工件的水平方向**做 `u`；
若基座也未标定，用主法向的水平分量（`auto_base` 里已经有这个 `h`，`:1809`）。

这一步直接把 `big` 从"倾角恒 0"变成"倾角可用"，是**收益最大的一处**。
验证方法：修完之后 `big` 的 `tilt_deg` 唯一值应当从 1 个变成多个，J5 超限点数下降。

### P1 · 补真基座位姿（而不是 auto_base 猜）

`auto_base` 是假设值（`:112` 注释写明"这是假设，不是标定值"）。
给了真 `basePose16` 后 `tiltRefW` 变成基座 ±X（`:1849`），退化消失。
但**注意**：实测若把基准换成基座 +X，`big` 的需求倾角会变成中位 60°、
100% 超工艺喷角 30°——因为这件是平放的、枪本来就该正对 +Z。
所以正确做法不是简单换基准，而是**按工件姿态选基准**（平放件用重力、立挂件用基座轴），
这一点需要现场确认。

### P1 · 展开方位作用域（方案 C 的 C1b，但优先级提前）

大平面上方位是唯一还活着的杠杆。实测同一最差点：

```
tilt=0°  az=0°  → J5=125.2°, margin=−5.23°
tilt=0°~35°, az=−60° → J5=85~86°, margin=+6.9~8.6°   ✅ 34 个候选全部过关
```

**仅仅把方位从 0° 偏到 −60°，J5 就从超限 5° 变成有 7° 余量。**
所以方案 C 把方位渐变列为"可选加强、先不做"是**优先级排错了**——
在大平面上，方位比倾角更有效（倾角还被退化卡住）。
建议把 C1b 与 C1 同时做，先放开到 ±90° 并单独报 `azUsedDeg` 分布。

### P2 · 里程渐变（方案 C 主体）仍然需要，但解决的是另一个问题

它解决"倾角是面级常量、远端被近端绑住"，在 `longstripe`（法向偏 36°、倾角不退化）
这类件上有效。但在 `big`（完全朝上、退化）上，不先修 4.1 就开 ramp 也没用。
**顺序应当是：修退化 → 展开方位 → 再做里程渐变。**

## 8. 需要你确认

1. **J5 余量下限设多少？** 现在 `jointMarginMin = 1.0°`。若提到 10~15°，
   `big`/`longstripe` 会立刻报更多 `JOINT_LIMIT`——这是**如实报**，不是变差。
2. **平放件（big）到底该不该倾斜？** 若工艺要求"平放件必须正对 +Z 喷"，
   那 `big` 的倾角恒 0 是**正确行为**，J5 超限就只能靠改方位或站位解决，
   修退化反而是错的。这一条必须先定，否则 P0 第二条会做反。
3. **方位能放开到多大？** 实测需要 −60°，现白名单正好卡在 60°。
   若允许到 ±90°，`big` 的余量还能再涨；但这意味着"从侧面斜插进枪"，
   需工艺确认（方案 C 第 7 节也是同一个待确认项）。
4. **`longstripe` 的整轨迹翻支要不要单独查？** 相邻点关节步长中位 180°，
   已经不是"姿态不好"而是"轨迹中途换机器人构型"。建议单独立项，
   与本轮的贴限位问题分开治。

# 9. 实现落地：`RS_POSE_TILT_J5` 叠加层（2026-11-10 晚）

## 9.1 结论先说

**「面内姿态可变」这条路线成立，且已验证：`big` 的 J5 贴限位从 8 点降到 0 点，
最差余量 −5.23° → +0.21°，|θ5| 最大值 125.2° → 108.7°（不再超限），P0=0。
代价是只倾斜了 8 个点（占 9761 个喷涂点的 0.08%）。**

关键设计判断（也是实现上唯一真正的坑）：**J5 必须是"叠加层"，不能是"另一套姿态方案"。**

## 9.2 为什么必须是叠加层

第一版把 `RS_POSE_TILT_J5` 写成阶段 2 的头号分支：危机点用解析解、**非危机点一律 `tilt=0`**。
即"J5 模式接管整套姿态"。9 算例 A/B 直接暴露三个退化：

| 算例 | 现象 | 根因 |
|---|---|---|
| complex | 关节步长 >5° 从 47 涨到 **93** | 基线全点 6.21° 倾角被抹成 0，姿态基准整体偏移，阶段 3 靠回退硬撑 |
| longstripe | P0 从 2 涨到 **22**（LINK_HIT 20 点） | 基线 40° 倾角是"把枪伸进窄槽"的避障刚需，抹 0 后连杆撞件 |
| longwide | 新增 7 点超限 | 基线 2.81° 是抬出浅槽用的 |

三个算例退化源头完全一样：**把非危机点的基线姿态丢掉了**。
基线（面级常量/逐点连续）负责"够得着、不撞、喷角合规"，J5 只该管"θ5 贴限位"一件事。

## 9.3 最终架构（`robot_safety.cpp` 阶段 3.6）

```
阶段 1  逐点倾角需求（基线，IK 种子连续）        ← 不再有 J5 分支
阶段 2  面级 / 逐点姿态决策（基线）              ← 不再有 J5 分支
阶段 2.5 连续性收尾（斜坡 + 枪体闸门）
阶段 3  按 final 重解 + 违规归集                 ← 这里拿到每点真实执行位姿 results[]
阶段 3.5 回退段统一姿态
阶段 3.6 逐点解析救 J5（新增，叠加）             ← 只改 |θ5| 超目标的点，其余一字节不动
         基准 + 拾升
```

阶段 3.6 内部三步：

1. **判定 + 解析规划**：`|θ5| = |results[i].theta[4]|`（真实关节角），超 `120 − jointMarginMin − 1` 才算危机点；
   用 `forearmDirOf(theta)` 取前臂方向 → `planTiltForJ5` 解析出 (倾角, 方位) + 预测 θ5。
2. **按连续段分组统一方位**：危机点按"允许夹 ≤2 个非危机点、且同 row"分段，
   段内用**空间向量和的圆均值**统一方向（避免 179°/−179° 平均成 0°），
   再逐点反算各自 az。**倾角不统一** —— 每点需求不同，强行统一会把"刚好够"的点推到撞件。
3. **逐点试执行**：过 `hardOk` + 腕部奇异防护 + "θ5 真的变小"三道门才采纳；否则退回基线。

## 9.4 两个必须记住的坑

### 坑一：前臂方向必须来自真实 IK，不能估算

第一版用 `analyticSeeds`（腕心近似下的 IK 种子）估前臂方向 a。
实测与真值差 **中位 28.6°、最大 59°**，导致：

- big 上 8005/9761 点被误判成危机点；
- 关节步长 >5° 从 3 点涨到 **407** 点；
- longstripe P0 从 2 涨到 **9342**。

`|θ5| = ∠(a, g)` 要的是**这一点的真实臂构型**，不是"猜一个够用的起点"。没有捷径。

### 坑二：U* 是纯运动学最优，几何要当否决权

`U* = −a_T` 只知道"这样能让腕子伸直"，完全不知道会不会撞。
窄槽件上"指向前臂反方向"往往正是把枪管顶进槽壁的方向——longstripe 27 个退回点里
`clr = −20.9mm` 的占一半，那是真撞。

解法：解析方向过不去时，**保持倾角、把方位扫 ±40/±75/±110/±145°**，
找第一个既过 `hardOk` 又把 θ5 拉下来的。方位改了 θ5 照样能变小
（θ5 只关心枪轴与前臂的夹角），只是不如 U* 省倾角。
longstripe 有 **25 点**是靠这层救回的。

### 附带修的坐标系 bug

`planTiltForJ5` 原来第 1 参传的是 `nBase`（基座系），函数内却当点云系法向用
去算切平面分解 `aT` 和方位角。已改为显式区分：`nCloud`（点云系，算方位）与
`nBase`（基座系，解析倾角），调用方传 `t.normal(i)`。
