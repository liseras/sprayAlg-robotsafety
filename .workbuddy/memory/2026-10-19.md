# 2026-10-19 重建面规则化（第四轮）

## 用户问题
WPF「显示重建平面」显示的是锯齿拼块（逐 cell 小方片），不是规则平面。
用户要求：同一方向上只有一个平面；棕色槽型盘的底面应当是**一个完整规则平面**，
孔洞填补阈值大时不该有洞。

## 根因
1. 面片是用占用网格逐 cell 画小方片拼出来的，边界必然是阶梯锯齿；
2. 区域生长把缓翘曲面切成上千块，< minPts 的块被丢弃 → 主面只覆盖板子的一部分（缺角）；
3. 近共面合并用"块质心偏移 < 3mm"判据，缓翘曲板各块质心相距十几毫米，合不上 → 同方向被拆成多个面、互相重叠；
4. 孔洞填补不判跨距，一律填（fillHole 只影响轨迹行）。

## 改动（spray_traj.cpp / spray_traj.h / driver.cpp / Native.cs / MainWindow.xaml.cs）
- **重建面改为矢量化轮廓**：细网格占用(cs 2~6mm) → 闭运算(桥接扫描线间隙) → 开运算(去细尾巴)
  → 按跨距判定的孔洞填补(span <= fillHoleSize) → 边界追踪(材料在左，外环CCW/孔CW)
  → RDP 简化(eps = max(2cs, 1.5×行距)，抹掉扫描线梳齿) → 凸包规整(仅当凹陷深度 <= max(5×行距, fillHole))
  → 最小外接矩形吸附(矩形度 >= 0.85 外环 / 0.80 孔) → 孔洞桥接 + 耳切三角化。
- 结构体 `SprayTrajPlane` 删掉 cells/cellSize/cellCount，改为 polyVerts(384×3) + polyTris(768×3)。
- 近共面合并判据改为「法向差 < 5° 且 块内点到目标平面最大残差 <= max(2×flatnessTol, 6mm)」
  → 缓翘曲板整片合成一个面，真实折边(>=5°)/台阶仍分开。
- **塌缩判定对"只分出一个面"也生效**（原来 out.size()>1 才做），把整片点云归给该面，
  否则缓翘曲大板只剩一块"主区"，重建轮廓缺角。
- 用重建掩膜回筛内点：落在开运算删掉区域的点不再参与轨迹，避免轨迹在工件外拉梳齿。
- WPF：按 polyVerts/polyTris 直接建 MeshGeometry3D，并用「只被一个三角形使用的边」描边界线(LinesVisual3D)。

## 验证

## 侧壁（近垂直面）检测 —— 2026-10-19 上午

用户指出"托盘有接近垂直的侧壁，为什么没有"。查证点云：棕色槽型盘局部法向 >40° 的点占 13.4%
（P90=60°、P95=79°），外沿确有一圈 ~35mm 高、与地面法向夹角 86° 的裙边。

**根因（4 条，都是方法论级的坑）**
1. 法向平滑把薄壁拉平：K=25 邻域里绝大多数是地面点，2 轮均值后侧壁点法向 ≈ 地面法向，
   区域生长根本分不出壁。→ 改成**保边平滑**（只平均与自身法向 ≤30° 的邻居）。
2. 先过滤后合并：区域生长把面切成几十块，`minPts(=2%)` 先过滤就把小块（含全部侧壁弧段，
   最大 177 点 < 272）扔了。→ 改成**先合并再过滤**（minSmall=0.15% 参与合并，合并完再按 minPts 筛）。
3. 合并用"漂移法向"：种子 13° 的斜坡块吸收 0.5° 地面碎块后重新拟合，法向"平均"回地面，
   簇身份错乱（表现为 876/540/395 三个"看着像地面"的假平面）。→ 角度判定改为**对固定种子法向**，
   并在簇级别做第二遍合并（此时法向已确定，不会再漂）。
4. 侧壁是窄带：块级合并永远拼不回一个面。→ 新增**侧壁 RANSAC 逐面剥离**：直接在陡壁点集上
   逐个剥最大共面集，自适应容差 1.0→1.6→2.2→3.0mm，校验要求 |n·Z| 夹角 >40° 且拟合 RMS ≤ max(0.5*tol,2.5)。

**参数标定（实测）**
- 合并角门限 8°：盘底碎块 0.3~1.0°，折型板折角 13.2° —— 8° 正好分开"翘曲碎块"和"真实折边"。
- 塌缩判定 `allNear` 的少数派容忍 8%：托盘斜坡占 9.7%、折型板折面占 46%；放宽到 15% 会把托盘侧壁吞掉。
- 侧壁法向必须**背离工件质心**定向（PCA 符号随机，朝内会把喷头送进工件）。

**新增**：残点归并（未归属点并到最近且在 max(tol,curvatureTol) 内的面，保证覆盖率）；
只有网格重建成功的面才计入 plane_count 并生成轨迹（plane0 恒为主面）。

**棕色槽型盘 flat=30 fill=300 结果**：2 个面 —— 地面 4 顶点矩形 205×309（内点 12195，15 行）、
侧壁 4 顶点矩形 187×56（内点 748，与地面夹角 87.7°，平面度 RMS 0.44mm，4 行）；共 19 行，
行内点距 3.82mm 均匀。侧壁喷头落在 y=-630（工件 ymin=-539，在外侧 100mm）。
flat=10 同样是 2 面；flat=3 时盘底翘曲 7mm > 3mm 容差，必然分裂成 7 面（符合参数语义）。

**已知遗留**：曲型板（曲面件）flat=30 会切成 8~15 片平面（固定种子门限的代价），
待后续用"曲面按弧长分条"替代。

### P1 面间过渡避障 —— 已实现

原来面间只有 1 个 `spray=0` 哨兵点（位置不变），控制器会把最后一个喷涂点和下一面首点直线插值，
等于一根穿过工件凸台/槽壁的斜线。改为 4 段式绕行：
沿上一面法向退出 `clear=standoff` → 抬到全局安全高度 `zSafe=工件最高+2×standoff`
→ 安全高度平面内平移 → 下降到下一面首点。

tray 实测：退出到 z=1791.8 → 抬到 1797.6 → 横移 343.2mm（全程 z=1797.6），工件最高 1597.6。
点距自检同步修正为"只统计 spray=1 的相邻点"，否则 5.8mm 的抬升小步会把 `seg_len_max`
从 4.03 抬到 5.83，看起来像点距失控。

查看器同步：空移段不再整段丢弃，改用**细灰管（直径 1.1）**渲染，喷涂行为红色粗管（2.5），
避障路径可见可验。
**关键判据**：必须按"段"分类而不是按"点"分类——只有**两端都是 spray=1** 的段才算喷涂段，
只要有一端是 spray=0 就是空移。关枪/开枪发生在点上，枪在 A→B 这段上的状态是"关"。
按点分类会把"抬枪上升"和"下降到首喷点"染成红色，看着像喷着飞过去（已在侧视图上暴露并修正）。

### 折型板面被切成"几块补丁"的根因
用户反馈"这里是一个平面才对"，截图红框内出现 3 个互不相连的深蓝小块。
实测定位（不是形态学问题，是数据问题）：
- 面1 = 板左侧约 46mm 宽的**折边带**（与主板面夹角 63.2°，长 729mm）。
- 该带点云沿长向**本身断成 4 段**：`[mesh] 闭运算后连通块=4`（rr=4 已开到上限仍接不上），
  开运算削成 3 段。即闭运算不是瓶颈，是点云边缘掠射造成的真实断续。
- 边界追踪得到 3 个环：15378 / 1135 / 542 mm²（碎环只占 1~2%），耳切后成 3 块独立网格。

**修复**：`build_plane_mesh` 边界追踪后按"相对最大环面积"过滤——
面积 < 主环 10% 的孤立环丢弃（原有 9cs² 绝对下限保留）。
效果：zhe 面1 从 17 顶点/11 三角/3 块 → 9 顶点/7 三角/1 块；complex 面1 也从 2 块并成 1 块。
真实多区域面（complex 面2 58%、curved 面2 54%/面4 45%）因占比 >10% 全部保留。

### flatnessTol 的真实作用面（重要，别再误判）
所有现场件的高度极差都 > `curvatureTol`(5)，**一律走"法向区域生长"分支**，
`tol` 在这一支里只影响：残点归并容差、塌缩判定 RMS 上限 `max(2×tol,6mm)`、侧壁去重位置容差 `max(tol/2,2)`。
它**不是**面间合并的角度门限（那个固定 8°）。所以 zhe 在 flat=30 与 40 下结果**完全相同**。
反过来 tray 从 flat=3（6 面）到 flat=30（2 面）差异巨大——差异来自残点归并容差，不是"合并门限"。
**不能**把 `span <= curvatureTol` 那个判定改成 `<= flatnessTol`：cao(24.9)、longstripe(38.7) 会被误塌成 1 面。

### 折型板遗留风险（已量化，待用户确认）
面1 的 4 行/行距 12.00σ=0 很规整，但轨迹**点云支撑度差**：
把轨迹投影回面后算到最近点云的距离，面0 中位 2.0 / p90 4.8 / max 7.7mm（好），
面1 中位 2.7 但 **p90 35.7 / 12% 的点 > 20mm**（悬空）。
原因是面1 的点云 80% 挤在一条 4mm 宽的棱线上，其余是主板面边缘混入的污染点。
逐面量化（verify_rows_per_plane.py）：面0 8 行/四边余量 +3.9/+6.4/+6.7/−2.8mm，
面1 4 行/行距 12.00 σ=0/行向偏离 0.38°/余量 −5.1/+4.4/+9.0/+9.6mm。

## 13:30 折边带"只重建出 42%"的根因与窄条面矩形补全

用户第二轮反馈："这里没有重建，那里只是缺陷比较严重，按理说需要重建"。
（先核对：桌面 `折型板(现场点云).ply` 与 `cpp/_regress/zhe.ply` md5 相同，是同一份数据。）

### 根因（不是没重建，是只做出来 42%）
折边带（面1）真实尺寸 777×43mm，但：
- 短向上 80% 的点挤在一条约 4mm 宽的棱线上（激光掠射），其余是主板面边缘混入的污染点；

## 第八轮：大点云性能优化（2026-10-19 14:50）

### 用户报障
"点云一旦大了之后，耗时太大了，想办法减少耗时"

### 结果
60.2 万点的大平面件：端到端 **20.5s → 1.85s（11 倍）**，算法内部 17.9s → 1.48s。
查看器：读点云约 2~4s → **150ms**，算法约 18s → **1.54s**。
**10 个回归样本的轨迹 CSV 与优化前逐字节相同**。

### 先量再改：加 `SPRAYTRAJ_PROF=1` 分阶段计时
`ProfStage` RAII 结构，析构打印 + 支持累加器。原始分布（60 万点）：
KD 构建 1076+1054ms、KNN 查询 5377+9122ms，其余（轮廓重建/轨迹）＜100ms。
**96% 时间在 KD 树和 KNN 上**，和"轮廓重建慢"的直觉完全不同。

### 五处改动（按收益）
1. **切分轴按最大跨度选**（最大单项，KNN 6µs→1µs）
   线扫点云是薄壳（1030×487×81mm），x/y/z 循环选轴时轮到 z 就切不动，
   节点等于没切开、子树巨大、剪枝失效。这条单独就让 60 万点快 2.2 倍。
2. **逐点阶段并行**（6 核 12 线程，实测 6~7 倍）
   SOR 邻域、法向 PCA、两轮法向平滑。静态分块，每块只写自己下标区间，
   结果与串行完全一致；SOR 的 sum 改为并行算 md[] 后串行求和，保住浮点累加顺序。
3. **`ls_plane` 逆迭代：逆矩阵只算一次 + 定点判据提前退出**
   原代码把 det 和 6 个伴随元素放循环里（都是循环不变量），
   而退出条件 `|det|<1e-20` 也是不变量 —— **条件永远为假，等于每点跑满 80 轮**。
4. **RANSAC：批量生成假设 → 并行打分 → 按原顺序取第一个最优**
   原来 200 轮 × 60 万点每轮都 push_back 索引（1.2 亿次 + 反复扩容）。
   因更新条件是严格 `>`，最终选中的就是"迭代序上第一个达到全局最大内点数的假设"，
   批量后按同序取第一个 → 结果完全相同。RNG 抽样顺序也保持一致。
5. **KD 构建：`nth_element` 原地中位切分 + 子树并行**
   原每层 std::sort 全排 + 左右拷贝子数组，O(n log²n) 且 2n 次分配。
   节点数恒等于点数 → 预分配 + 原子槽位分配 + 左右子树并行（>6 万点才开线程）。

### 两个非算法热点（原来比算法还显眼）
- `driver.cpp` 读 PLY：逐行 stringstream + 每行一个临时 vector<double>，60 万行 1.3s
  → 整文件读入 + strtod 扫描。
- `PlyReader.cs`（查看器）：`BinaryReader.Read()` 逐字节读行，3000 万次虚调用，
  再加每行 Split + double.Parse → `File.ReadAllBytes` + `Utf8Parser.TryParse`
  （零分配且正确舍入）。顺带修了二进制 PLY 未识别属性不计入步长的错位隐患。

### 教训
**性能改造的验收标准是"输出逐字节相同"，不是"看起来一样"。**
`ls_plane` 收敛判据一度用相对阈值 `|dot|>1-1e-13`，肉眼零差别，
但 complex 件有 8 个坐标差 0.19mm；改成"定点判据"（迭代结果停止变化）后重新一致。
另外：**"慢"必须先分阶段计时**，猜热点必猜错。

## 第十一轮（18:10）："轨迹看着乱"的定位与修复 —— 枪姿连续性加强

用户原话：**"重建很好，但是这轨迹显然不规则啊，乱七八糟"**（附查看器截图）。

### 定位（先取证）：乱的**不是行**，是**枪位**
`SPRAYTRAJ_DUMP=1` 新增导出 `surf_rows.csv`（行号,序号,x,y,z,s=p·eIdx,nx,ny,nz）离线体检：
- 行点很规整：行内 s 漂移 ≤1.6mm；步距中位/p90/p99 = 4.00/4.00/4.05mm、最大 7.7mm（无桥接）；14 行在平均面内就是直线。
- CSV 里的点是 **枪位 = 面点 + 100mm×法向**：100mm standoff 把法向 1° 误差放大成 **1.75mm 横移**；
  逐点 PCA 法向 1~2° 噪声 → 枪位二阶差分 RMS **3.29mm**、最大单步 **51.1mm**、`>8mm` 步 **222** 处。
- 行端换墙（左端 80° 陡壁）/折边（右端 40mm 内转 55°+）处单步转 15~30° → 枪位横甩 10~50mm。

### 修复（`gen_surface_rows`，只动 `rowN`，`rowP` 一字不动）
1. 行内 `[1,2,3,2,1]` 低通 **×4 遍**（等效高斯 σ≈6.5mm）压逐点噪声；
2. **双向角速率限幅 6°/步**（≈1.5°/mm）：前向+后向各扫一遍，把折角摊成缓转（单向会把落后角累到行尾）。

### 端部"折返/钩子"= 几何，不是抖动（已算清，等用户拍板）
左端陡壁/右端折边处法向在 ~40mm 内转 55~80°，而枪位在面外 100mm →
**凹折的等距偏置面必然自交**（折边曲率半径 ≪ standoff），每条行端部折回 ~58mm（右端实测）。
三条路（互斥）：A 保持（喷角优先）/ B 折边处**分行**（平台拆成独立子块各自布行，需改切分+发射）/
C 收紧限幅（折返变浅但要 ~35° 偏角）。见 HANDOFF 6.4⑥。
