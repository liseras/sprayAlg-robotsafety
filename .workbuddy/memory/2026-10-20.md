## 第十五轮：回转体（垃圾桶/截锥）轨迹沿母线放射

用户报：「轨迹不规则，如果点间距小姿态变化大可能会出问题」，件 = 垃圾桶(模拟生成).ply
（43469 点，二进制 PLY，用 bin2ascii.py 转 ascii 后入库 cpp/_regress/bin.ply）。
真实几何：顶环唇边(z184, r143→175) + 圆台侧壁(r60→175, h191) + 底面圆盘(r57)，三块连成 100% 的块。

三个根因：
1) **行走向**：surf_march 的切向是 cross(n, eIdx)，等于「等 eIdx 的平面截线」。
   柱面上截线正好沿长边（所以曲型板没暴露），回转面上截线是双曲线 → 每条行沿母线
   从顶沿直插轴心，27 行全在中心抱团；母线间距外圈 20.4mm / 内圈 7.0mm（设定 12mm）；
   外沿还有 r 到 199mm 的外推钩子（点云最大 r 只有 175）。
2) **平盘混进曲面块**：沿 n0 的高度场在水平盘上是常数、梯度 0，等值线无定义 →
   追踪退化成直线横穿整个曲面。
3) **姿态限幅写死 6°/点**：4mm 点距 + 200mm/s = 300°/s 末端角速度，多数六轴跟不上。

改法：
a) gen_surface_rows 加回转面判定（三项合取：沿长轴高程起伏 >0.10、投影方位覆盖 ≥300°、
   宽高比 <1.8）+ surf_march 加 isoH 模式（上坡方向 = ∇h = n0·(n·n0) - n，行 = 等高线圈）；
   锚点改逐层等弧长推进 h += L·|∇h|(该层)。**宽高比那一条是给曲型板留的** —— 它高程起伏
   0.372、方位覆盖 100% 都能过，只有 548×176(3.11) 把它挡回去，否则行被切成 6 个点的碎片。
b) detect_curved_patch 加块内平盘剥离：沿 nf 的 1mm 高度直方图找尖峰，峰值 ±0.2×行距
   的点占块 ≥5% 且 2D 最小宽度 ≥3×行距 → 剥出去走平面路径，最多 3 轮。
   **不能用 RANSAC** —— 锥面在 2.4mm 公差下能凑出 3043 点伪平面 (0.85,-0.25,0.46)，
   把真正 2726 点的底面比下去，底面永远剥不出来。
c) 限幅角 = 150°/s × 点距 ÷ 速度（夹 0.5~6°），200/4mm → 3.00°/点。
   driver 加 -row/-pt/-so/-sp 四个参数，能复现界面任意组合。

结果：垃圾桶 1 面 27 行 → 3 面 57 行；锥面 18 圈 / 行距 12.00mm / 覆盖率 100% /
贴合残差 1.65mm（改前 93.1% / 5.19mm）；gun_jitter p95 5.2、normal_step p95 3.02°。

## 倾角策略：从「45° 阶梯」改成「按法向线性给」

用户一句「应该按照法向方向线性给倾角」——原实现是 `n_z < cos45°` 就一律 20°，45° 边界

1) 候选网格不能写成 `tilt0 + k·step`。tilt0 随法向连续变化 → 候选相位跟着漂移。

   `ceil(tilt0/step)*step` 起按 5° 整数倍走。az 兜底的 ttBase 同样改。

2) 早停判据原来只比 clearance："连续 4 档变化 <0.5mm 就停"。可间隙常常早早饱和到
   search 上限 120mm，饱和区里自碰撞/关节余量还在随倾角剧烈变化 → 误停，漏掉能过关的档位

## 通用性核对（用户问"通用嘛"，第十七轮之后）

用户问这轮改动是否通用。核对结论分三层，写给下次别再说满：

**一、第十七轮改动本身是通用的** —— 4 条判据全是相对量，无一处写死工件类型/尺寸：
`moveClear = max(6, 0.25·standoff)`、`zSafe = zPartMax + 1.3·standoff`、
采样步长 `<=2·pstep`、关枪判 `枪位行程 <= 3L`、平面跨段 `gap > max(3·turnR, 3L)`。
9 个有空移的样本全部下降（-2%~-58%），4 个单面件（panel/synth/big/longwide）本来 0 空移、不变。

**二、整套算法的形态覆盖分档**（依据是分支结构 + 样本实测）：
- 平面/多面体（平面为主）：强。连通域+法向聚类+平面拟合+内点重投影，与形状无关。box 5 面/12028 点稳。
- 可展曲面（管/型材/弯板）：较强。行走向用面内主曲率方向 `cross(n,eIdx)` 逐点追，不假设参数方程。
- 回转面（锥/柱/球/盘）：中。靠 `isoMode` 三项合取启发式（高程起伏>0.10、方位覆盖>=300°、宽高比<1.8），
  不是严格的"是否回转"判据。
- 环形窄面（法兰/端环）：中偏弱。`detect_ring_uv` 四条阈值（方位>=34/36、环宽<=2.5L、
  内径>=0.45外径、外径>=3环宽），超范围静默退回平行扫描。

**三、明确没验证过的形态**（对外不能说"都能用"）：
1. 深腔/内壁遮挡 —— 扫描仪打不到，点云缺失会漏喷（不是算法问题，但没有补扫机制）
2. 强扭曲自由面（既不可展也不回转，如叶轮/雕塑面）—— 现有分支都不匹配，退回平面布行，陡峭段行距失控
3. 悬垂/倒挂面 —— 法向朝下时枪位在面下方，`zSafe` 的"往上抬"逻辑不成立（真实 bug 风险）
4. 多件拼装 —— 件间缝隙可能被并入同一连通域或切碎，未测

**四、与工件无关的通病**：面与面交界（棱边）处法向被邻面点污染 → 姿态角速率超标。
任何"两个面相交"的工件都会遇到，bin 的 row0 偏 21° 就是这个。即 HANDOFF 第 7 节第 19/21 条的棱边避让。

## 急转弯诊断（用户问"这种急转弯机器人怎么处理的过来"）

用户看 3D 截图质疑转角太急。量化结论（`bin.ply -row 12`，脚本 `E:/tmp_build/turnstat3.py`）：

- 剔除步长<0.6mm 的退化点后，3420 个有效点；
- 转角中位 3.1°、p90 9.7°、**p99 98°**、最大 174°；
- **>60° 共 61 处（喷涂段内 56 处）**，**>120° 共 23 处（喷涂段内 20 处）**。

两类来源完全不同，不能一起修：

1. **往返式扫描的端点掉头**（z≈100 的平环、底面平行扫描）：一条线走到底后
   **原路退回**，只是横向错开 3.5mm。实测 idx3584(56.07,9.80) → 3585(57.14,13.09)
   → 3586 同点(零长) → 3587(54.93,9.83)，转角 165°。
   注意错开量只有 3.5mm，**不是行距 12mm** —— 因为平环上是"弦"扫描，两弦在圆周端点收敛。
2. **等高线圈的圈间过渡**（锥面 z=143/175/191/202/225）：本圈结束直接跳下一圈起点，
   方位差 + 径向偏移 + z 跳 0.57mm，转角 120~146°。

根因：`sampleArc` 的圆角分支（`turnR=0.5L`）只在 `gap <= turnR*3` 且两段端点**不重合**时生效；
端点几乎重合时弧退化，直接连成尖角。曲面块走 `emitGap` **纯直线插值，根本没有圆角**。

**另一个更硬的 bug**：零长段普遍存在 —— box 240 个、complex 62 个、cao 44 个、tr 42 个、
bin 18 个（`E:/tmp_build/dupstat.py`）。控制器的速度规划会除零，KUKA/ABB 直接报
"motion not possible"。来源是轮廓扫描首尾点重复 + 过渡哨兵点。

**方案（未实施，待用户拍板）**：①端点掉头改 U 形 overspray（枪沿原方向出界约 0.5×行距，
半圆连接），工业标准做法，避免边缘停枪流挂；②圈间过渡改径向直滑；③全局删零长段；
④>60° 转角统一圆化后处理。①会让枪跑出工件边界，属于工艺决定，需用户确认。

图：`outputs/round17/turn_diag.png`（左 3D 全轨迹+23 个尖角标记，右端点掉头局部放大）。

## 碰撞按部位拆分：连杆逐点全判（用户指出"不能只判末点"）

用户看图后提两点：倾角要按法向线性（已做），且**不能只判末端，连杆会不会撞原始点云也要判**。
第二点是真缺陷：`linkStride=3` —— 每 3 点才判一次连杆，其余 2/3 的点只判枪体。
即"连杆会不会撞"有三分之二的点根本没查。改成 1（逐点全判），性能用剪枝补：
某段连"当前最差表面距离 + 半径"都够不着时跳过 KD 查询 → 10 样本 24s（原 22s）。

**分开报枪体/连杆是这次最有价值的产出**。两类撞的处置完全不同（枪体撞改喷距/角度，
连杆撞改站位或整条姿态），混成一个"最小距离"现场没法决策：
- longstripe：枪体 21.50mm 安全，连杆J3-J4 **−8.56mm 穿透** → 只看喷嘴会判"通过"
- big：枪体 47.14mm 很宽松，连杆J3-J4 29.68mm 才是压线的那个

API 变更（ABI 已重新核对 Point 216 / Result 296，C# Marshal.SizeOf 与 C++ offsetof 逐字段一致）：
- Point 加 clearanceToolMm / clearanceLinkMm / worstKind,worstJ0,worstJ1 / linkKind,linkJ0,linkJ1
- Result 加 minClearanceToolMm / minClearanceLinkMm
- 违规位加 LINK_HIT(1<<8) / TOOL_HIT(1<<9)，byRule 8→10；COLLISION 保留位序但**不再置位**
  （否则 byRule 重复计数）
- tiltNonUpDeg 默认 20→30：α=90° 竖直侧壁给到工艺喷角上限（用户图里"法向垂直时倾角给最大"）

**又一个统计口径不一致的坑**：过渡点抬升只 `pr.clearance += lift`，没同步 clrTool/clrLink，
于是 curved 出现"总结论 20.02 已避开、连杆最小距离却还是抬升前的 11.39"。凡是分组统计
必须和总量同口径更新。另一个：IK 失败点写 0 会被读成"贴脸 0mm"，一律写 nan。

边界（要跟用户讲清）：碰撞逐点判，不是连续扫掠；点云只有可见面，连杆从背面穿过看不到
（单视角扫描尤其危险）。方位目前仍是"向上优先 + 失败时 ±30/60 兜底"，还没做到
"按机器人站位选哪一侧进刀"。

提交 3eec394。截图：wpf_shots/big_link_bottleneck.png（连杆瓶颈）、longstripe_reject.png（枪体安全但连杆穿）。

## 第十八轮：急转弯治理（实施完成）

用户："这种急转弯机器人怎么处理的过来呢" → 说"实施"。

**指标换成曲率半径**：`r = 段长/转角`。逐点转角有误导性（圆弧上点距越密转角越大），
改前用逐点转角看是"56 处 >60°"，用曲率半径看是 **min 0.04mm、514 处 <3mm**。

**根因不是转弯急，是点距坍缩**：bin.ply idx673~685 连续 13 点只走 1.3mm（点距 0.03mm），
切向由噪声决定 → 曲率 0.03~0.1mm。机器人看不出 0.05mm 抖动，但速度规划会当成原地掉头
（a = v²/r = 800 m/s²）。

**三条弯路（都试过、都失败，别重走）**：
1. 二次贝塞尔 + 侧向控制点 → 端点切线不连续，>60° 从 61 涨到 91 处
2. 三次贝塞尔 + 切线控制点（C1 连续）→ 横向错开 δ 太小，掉头半径上限 δ/2，
   <3mm 从 500 推到 606 处
3. 判据用"两端 z >= zPartMax+0.5·standoff" → 差 9mm 漏判（前一轮已记）

**最终方案（输出前统一后处理，不碰生成端）**：
1. 删零长段（spray 相同才删）：box 240/complex 62/cao 44/tr 42/bin 18
2. 密集区等弧长重采样（只动"连续点距<0.5pt 且链长>1.2pt"，bin 719 点）
3. 探出点消除 + 发卡弯倒角（转角>150° 且 |AB|<3pt → 删拐点直连，带 partTree 撞件校验，
   **迭代到收敛**：删一个会接出新短段，单遍只抓 1 处，迭代能抓 4 处）

**结果（bin）**：曲率 min 0.04→0.63mm、<3mm 514→65 处(-87%)、<5mm 703→76、
步长<0.5mm 570→4、零长段 18→0、点数 3856→1711(-56%)、seg_mean 1.679→3.768、
seg_max 3.996→4.000；覆盖率（工件点到最近枪位）中位 67.4/p99 100.6 **逐位一致**，零漏喷。

**回归 28 样本**：27 个只少掉等同于零长段数量的点，seg_mean 全部更接近 4.0，rms/rows 不变。
同口径曲率对比：box 231→231、cao 38→38、zhe 16→16、longstripe 86→86（不变）。
注意：改前 box 显示"<3mm 0 处"是零长段让曲率计算跳过这些位置的假象，
删掉零长段后 231 处才暴露——这是既有问题，不是本轮引入。

**遗留**：bin 剩 65 处（底面圆盘平行弦行末，横向只错开 3.9mm，物理上限 1.95mm，
要改成螺旋扫描）；平面件 16~231 处（sampleArc 二次贝塞尔端点切线不连续，
改成真圆弧即可，会动所有平面样本）。
