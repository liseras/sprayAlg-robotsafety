## 第四十一轮：安全层改成「面级姿态常量」

用户要求：「在同一个面中喷涂的过程中，喷角即姿态尽量不要去改变」。
上一轮的 `smoothOnlyUp`（只升不降限幅平滑）做不到这件事 —— 它只保证 `|Δθ| ≤ 3°`，
保证不了同一面内倾角不变。盒子实测一笔 77 点里倾角 `30° → 55° → 30°`。

**为什么这件事值得改**：倾角是绕面点的球面旋转，TCP 位移 `2·standoff·sin(θ/2)`，
`standoff=100mm` 时 30°→52mm、60°→100mm。相邻两点方位再翻 180°（同倾角一上一下），
两个 TCP 相差 `2×100×sin60° = 173mm` —— 界面上是长刺，实机是一次甩腕。

**改法**（`cpp/SprayTrajCore/robot_safety.cpp` 阶段 2）：
- 法向夹角 ≤2°（`kSameFaceCos`）、沿法向偏移 ≤2mm（`kSameFacePlaneMm`）的相邻行归成一个面组；
  一个面组只允许一个 `(tilt, az)`。
- 面组姿态靠抽样打分择优，比较次序：P0（穿透+不可达+自碰撞，带 `2%×抽样+2 点` 容忍带）
  → 工艺喷角 ≤30° → 间隙不足点数 → P0 精确比 → 倾角小 → 方位趋 0。
- 采样三段式：`S1=16` 粗筛 → 容忍带 partition → `Sfinal=96` 复核 → 仍有 P0 则 `Sbig=400`。
  **所有候选必须同一采样数**，否则会挑出「只在小样本上好看」的姿态。
- 阶段 3 回退改成「最小偏离优先」：先 `±1×tilt_step`，不行再 `±2`、`±3`。
- 删除 `smoothOnlyUp`、删除 `stanceRow`；不可达点要写 `bad.sprayAngle = tilt`，
  否则 `tilt_deg` 列在 IK 失败点落成 0，看起来像倾角跳变。

**A/B（10 样本，同一轨迹 CSV，逐字节可复现）**
- `synth/panel/tray/zhe/big` 逐值不变；
- `complex` 改姿态行 3/31→**0/31**、倾角行内步进 3.0°→**0.0°**、TCP 突跳 17→**0**、关节步进 max 3.6°→**0.8°**；
- `curved` 33/41→**2/41**、倾角 max 60°→**30°**、关节步进 13.6°→**1.7°**、SPRAY_ANGLE 45→0；
- `longwide` 5/49→**0/49**、TCP 突跳 24→0、关节步进 179.9°→**3.1°**、NEAR_SINGULAR 88→3；
- `longstripe` 44/44→**12/44**、TCP 突跳 495→50，但 **P0 20→26**、SPRAY_ANGLE 5921→11290；
- `cao` 倾角行内步进 3.0°→**5.0°**（回退点造成）、关节步进 163°→179.7°（原有问题）；
- 开口盒子：倾角行内步进 **60°→30°**、改姿态行 119/221→73/221、TCP 突跳 1420→320、
  最大 176.3→122.8mm、枪轴>90° 8→**0**；回退 1411→1417 点。

**两处代价（不是回归，报告里要写清）**
1. `longstripe` 整件只有 1 个面组 11290 点，整面只能一个姿态，`(59.1°,0)` 仍超 30° 喷角。
2. `longwide` 整面从均值 2.9° 被抬到 **20.0°**（12476 点全同一姿态，仍在 30° 内）。
3. 盒子 face2（+X 内壁）`(30°,0)` 下 400 点全不可达，`(60°,±)` 能解却穿透 20+ 点 ——
   盒腔 292 / 枪长 150 / 喷距 100，这面不存在「整面都行」的姿态。

**跨实现口径**：`robot_safety/planner.py::_face_groups` 也是面级常量，但择优简化为
「取面内各点需求的最大值」，不搜索。`tray` 上 C++ 均值 4.1°/最大 29.2°，Python 2.7°/19.5°。
**对数时只比「姿态是否面级常量」，不要逐点比倾角数值。**

## 第四十一轮补：回退段统一姿态（阶段 3.5）

面级常量解决的是「不需要偏的点」，剩下的刺来自「必须偏的点」：逐点回退在同一面上造出阶梯
—— 盒子 1417 个回退点落在 **81 段**里（中位 8 点、最长 187 点），其中 18 段在十几个点内
连着 `30°→40°→55°→30°`。这仍然违反「同一面内姿态不变」。

**做法**（`robot_safety.cpp` 阶段 3.5，在阶段 3 之后、生效行数统计之前）：
相邻回退点（允许夹 ≤2 个非回退点、不跨行）归成一段，段内只用一个姿态。
候选 = 段内逐点用过的姿态 + 面级姿态；按「段内硬约束失败点数 → 偏离面级姿态」择优。
容忍带 `max(1, 2% 段长 + 0.5)`，超出的点**各自保留原样**，绝不为整齐牺牲硬约束。

**踩到的坑**：候选打分里写了 `for (k...; k<=b && fail < bestFail; ...)` 提前跳出。一旦某候选
`fail==0`，后续候选就完全不评估、却因 `fail(0) < bestFail(0)` 恒假而记成 0 失败 —— 于是
按「偏离最小」把**面级姿态**挑回来了（它恰恰是过不了才退的那个），段统一永远空转
（cao/盒子 统一=0 段）。去掉提前跳出、每个候选完整评估后才生效。

**效果（最终 A/B，10 样本）**
- `cao`：倾角行内步进 5.0°→**0.0°**、改姿态行 1/30→**0/30**、TCP 突跳 1→**0**（最大 9.6→4.4mm）
- 开口盒子：TCP 突跳 320→**283**、倾角变化段 63→**37**；P0 与最小间隙不变
- `longstripe`：TCP 突跳 50→**36**；`complex/curved/longwide/synth/panel/tray/zhe/big` 不变
- 回退点计数从「过程账」改成按最终位姿重数（段统一会让夹在中间的点也采用段姿态）

**盒子的 P0=2596 与本次改动无关**：IK_FAIL 2104（11%，基座是自动假设的 `-253,150,-197`）、
LINK_HIT 390、TOOL_HIT 102，最小连杆距离 −13.40mm（J6，idx 10294）。姿态已经规整，
这个件要在真机上过，得给手眼标定的基座位姿或改站位 —— 再加大倾角只会更糟。
`SPRAY_ANGLE` 9464 点（49%）也是同一件事：30° 工艺上限 vs 盒内 30~60° 的物理需求。

## 第四十一轮补二：面组打分的两个致命口径（热种子 + IK 救援）

上面那段"盒子 P0=2596 与改动无关"是**错的**，这个补丁把它修掉了。真正的原因有两层：

**1. 面组打分用冷启动 IK。** `scoreFace` 给每个抽样点传 `nullptr` 种子，而阶段 3 是接着
上一点解的。于是 +X 内壁 2104 点在 9 个候选下全是「冷启动 400/400 不可达」，选优只能
退回「倾角最小」，整面 30° 一个都解不出。改成**热种子链**（失败则断链重冷启）后：
IK_FAIL 2104→**133**、可达 89.0%→**99.3%**、P0 2596→**864**（比改动前的 1302 还低）。

**2. 阶段 3 对 IK_FAIL 直接认输。** 原来解不出就写不可达，不试任何别的倾角。加了「同方位
、倾角 ±1/2/3 步」的救援（过硬约束才用，记 reverted）后，`longwide` 单层那 15 个点
（面级 10° 下解不出、20° 下全好；15/12476=0.12%，400 点抽样的期望命中只有 0.5 个，
抽样永远看不见）P0 从 15 回到 **0**，结论也从 REJECT 回到 PASS_WITH_WARNINGS。

顺带加了「前 3 名候选的连续段复核」：抽样点相隔上百毫米，热种子在抽样上和在真解上不是
一回事 —— `longwide` 就因此先选了真解里 15 点不可达的 10°。现在前 3 名各取 3 段 64 个
连续点按阶段 3 的方式解一遍，硬约束全过的优先。

**最终 A/B（10 样本）**：`synth/panel/tray/zhe/complex/curved/cao/big` 不变或更好；
`longwide` P0 15→0（修复中）、`longstripe` 仍是 P0 20→26（整件 1 个面组，代价）；
开口盒子 P0 1302→**864**、可达 96.4%→**99.3%**、倾角行内步进 60°→30°、
TCP 突跳 1420→297（最大 176.3→137.9mm）、枪轴>90° 8→2、回退 2885→1585。
盒子仍 REJECT，但原因是连杆物理穿透（LINK_HIT 539 / TOOL_HIT 102，最小 −21.2mm），
不是姿态 —— 必须给手眼标定基座位姿或改站位。

## 第四十三轮：界面还在跑旧库 + 退回逐点最优时翻方位的漏网之鱼

**用户问」为什么轨迹乱七八糟「（贴了界面截图，REJECT 可达 18403/19125）。**

### 主因：界面目录的 SprayTraj.dll 是 10-22 17:39 的旧库

`wpf/SprayTrajViewer/bin/Release/net9.0-windows/SprayTraj.dll`（448KB）与构建目录
（484KB）**内容不同**。工程里虽然有 PostBuild 拷贝（`SprayTrajViewer.csproj:26`），
但只有 `dotnet build` 才触发，而这轮只重编了 C++。于是前两轮的「面级姿态常量 +
回退段统一 + 热种子 + IK 救援」**从没进过界面**。

判别方法（不用看文件）：界面数字对不上就是旧库 —— 旧库 不可达 722 / 回退 2878，
新库 133 / 1299。已给库加 C ABI `robot_safety_build_stamp()`，结论卡最后一行打印
`算法库：Oct 23 2026 13:22:33`；没有这一行 = 旧库。

**踩坑**：cmake 增量构建对共享源文件（`robot_safety.cpp` 同时属于 `SprayTraj.dll`
和 `spray_safety.exe`）的依赖跟踪失效，改了源码 `cmake --build` 报成功但 exe 时间戳
不变、行为也不变，白跑了两轮 A/B。**必须 `rm safety_driver.obj robot_safety.obj` 再编**。

### 次因：阶段 3 退回逐点最优时会翻方位

面级 `(60°, 0°)` + ±3 步倾角都过不了硬约束时，原代码 `pr = cache[i]` 直接退回阶段 1
逐点自搜的位姿，**方位可能是 60°**。开口盒子 idx 7070：

| | 面级 (60,0) | 缓存 (55,60) |
|---|---|---|
| clearance | 0.89mm | 0.93mm |
| 相邻点 TCP 位移 | 8.7mm | **83.1mm（实测）** |
| 硬约束 | 不过（self −0.38） | 也**不过** |

两个都过不了，退回只是把"撞"换成"另一种撞"，代价 83mm 甩腕。改成：
1. 先试「面级方位 + 该点最优倾角」（方位不变）；
2. 缓存原样退回只认方位相同的、且必须 `hardOk`；
3. 都不成立就保持面级姿态，违规照实报。

P0 864→**1113**（LINK_HIT 531→606、SELF_COLLISION 98→272）：这些点本来就在撞，
只是以前撞在别处还顺带甩腕；现在照实报。盒子仍 REJECT，根因是基座未标定

剩下 148 条长段全在**面组边界**（法向差 ~48°、倾角恰好相同），是"换面时允许改姿态"

A/B（10 样本）：`synth/panel/tray/zhe/big/complex/curved/cao` 不变或更好；

## 第四十四轮：回答「为什么逐点最优而不是规整优先」——顺带三个防御性修复

**结论：架构本来就是规整优先，逐点只是"面级姿态过不了硬约束"时的补救，而且它确实在被"不撞"驱动，不是被"最优"驱动。**

### 实测（开口盒子 19125 点）

面级姿态下过不了硬约束的点 = **1843 个**，分类（口径与 hardOk 严格一致）：

| 原因 | 点数 |
|---|---|
| 关节超限 `over` | **1111**（60%） |
| 真穿透 clearance<0 | 634（34%） |
| 自碰撞 selfGap<0 | 66 |
| 仅间隙不足 0<clr<2mm | **32（1.7%）** |

把 `-hardclr` 从 2mm 放到 0，回退点只从 1300 降到 **1281**（−19）。所以"2mm 余量把好点逼着回退"
这个猜测不成立 —— 逐点回退 98% 是在救"真扭不过去 / 真穿模"的点。

回退后这 1300 点间隙 22~35mm、零碰撞违规，只带来 34 个 TILT_JUMP。

### 试过但否掉的方案：把 over 计入面级 P0

直觉是"面级就该避开关节超限"，试了。face3 从 `(60°,0°)` 变成 `(60°,−60°)`，再放宽到
`(60°,−120°)`：

| 面级姿态 | 关节超限(逐点需救) | 整面方位 | 与相邻面交界 TCP 突跳 |
|---|---|---|---|
| (60°, 0°) | 1111 | 0（正上方） | 0 |
| (60°, −60°) | 835 | 歪 60° | 100mm |
| (60°, −120°) | 560 | 歪 120° | **152mm** |

**减少逐点回退的唯一手段是让整面斜着进枪** —— 膜厚沿面倾斜、枪可能蹭开口边缘。否掉。
代码里把 `over` 留在 FaceScore 里**只统计不择优**，并写了长注释说明"这是刻意的，别修"。

### 顺带三个防御性修复（对 10 样本 A/B 零影响，逐行一致）

1. **面级复核名额 8→16、粗筛 16→32**。face3 的候选池里 `(55°,30°)` 在 S=16 时分到"6/16 失败"
   排第 9，而终选只在 keep 名前挑 —— 它永远没机会。采样越少绝对数越不可比。
2. **方位白名单 ±60°**（`pushAz` 与广搜两处）。之前能选出 −120°（从侧面斜插），超出
   "上翻方向左右 60°"的工艺极限。
3. **`[pool]` 打印标注每个候选的采样数**。之前把 S=400 复核过的和 S=32 粗筛的混在一起打，
   看着像"P0=6 的候选排第 9"，其实是两把尺子。

### 排查工具

`RS_PROFILE=1` 新增 `[fb]` 行：`面级姿态过不了硬约束 N 点：穿透 a · 自碰撞 b · 间隙不足 c · 关节 d · IK e`。
这是回答"要不要救"的唯一可靠依据，不要凭感觉调 hardClearance。
