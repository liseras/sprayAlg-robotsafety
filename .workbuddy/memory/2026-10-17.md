## flatnessTol 失效根因修复：迭代最小二乘 → 真 RANSAC（完成）
- 用户问：为什么 flatnessTol=1mm 还能把凸起几十 mm 的点拟合进平面？
- 根因：fit_plane 名为 RANSAC 实为迭代最小二乘。最小二乘最小化全部点平方误差，成片凸起会把平面拉偏、把自己"吸"进内点集，tol 判定形同虚设。
- 修复：改为真 RANSAC（随机抽 3 点定平面→内点投票→内点最小二乘精化→按 tol 重收内点），迭代次数按内点率 0.3、95% 置信度自适应（200-800）。
- 新增：SprayTrajResult 增加 plane_cx/cy/cz（质心）、inlier_points（内点数）；WPF 加「显示重建平面（半透明）」复选框，渲染拟合平面网格 + 结果区显示内点占比。
- 验证：面板 100% 内点（纯平面）；长板中间带条形纹 1mm 阈值内点仅 55.6%（条形纹/凸起被正确剔除）；折型板 78.6%（折弯另一面剔除）；面板/槽型盘轨迹回归无退化。

## 底面多平面重叠 + 台阶真实高度口径修正（完成）
- 用户两次问"为什么底面这么多个平面重建，有重叠"；最新纠正"折边突起完全不止15mm"。
- 关键认知错误修正：之前用"整体最小二乘拟合残差"估算台阶高度是错的——整体拟合会把台阶"摊平"到全平面，残差被稀释，严重低估真实台阶。正确口径是**沿主平面法向的带符号距离分布**。
- 实测真实台阶高度（沿法向）：
  - 槽型盘：凸边 ~15~20mm，P99.5=15.1，但边缘局部达 42mm（P99.9=33.7，可能噪声/反光）
  - 折型板：翻边 ~30~34mm（P99.5=30.8，max=34.2）
  - 棕色槽型盘：深台阶 ~35~52mm（P99.5=35.4，max=51.7）
- 根因：split_planes 第一级判定原来用"整体 RMS <= curvatureTol"判断单面，但 RMS 是平方平均，小面积高台阶被大面积平坦底面稀释（槽型盘整体 RMS 仅 4.97mm 却真实台阶 15~42mm），导致凸边/翻边漏分割、喷不全/撞枪。
- 修复（spray_traj.cpp split_planes）：第一级判定改用 **残差 P99.5**（高分位）替代 RMS——P99.5 <= curvatureTol 才判单面直接返回（不切分不重叠）；P99.5 > curvatureTol 说明存在真实台阶/凸边 → 进入顺序 RANSAC 多面分割。
- 验证：折型板 P99.5=31.4→分割出底面+翻边(法向0.94,0.09,0.32)；槽型盘 P99.5=13.3→底盘+凸边+侧边4段；棕色槽型盘 P99.5=33.9→底盘+深槽侧壁(法向-0.08,-0.99,0.06近竖直)+台阶。
- 结论：底面"多个平面重叠"根因是旧版顺序RANSAC用紧tol(flatnessTol)把单一微弯底面切成多块、各块分位数包围盒重叠；现改"先整体P99.5判定"后，平缓底面直接单面不切，真实台阶才分割，重叠消除。

- 用户指出"折边突起完全不止15mm"，且"阈值给到20，槽型盘4边折起面还是该在，至少5个面"。
- 实测真实台阶高度（沿主平面法向的带符号距离，非整体拟合残差）：
  - 槽型盘：凸边 ~15~20mm，局部达 42mm；折型板：翻边 ~30~34mm；棕色槽型盘：深台阶 ~35~52mm。
- 根因（两处同源，都用 RMS 判据抹平台阶）：
  1) split_planes 第一级判定用"整体RMS<=curvatureTol"，槽型盘整体RMS仅4.97mm却真实台阶15~42mm → 漏分割；
  2) 共面合并用"合并后RMS<=curvatureTol"，把已分割出的凸边（14%点、高13mm）又合并回底盘（RMS被稀释到4.9mm）→ 凸边轨迹丢失。
  RMS 是平方平均，对小面积高台阶不敏感，必须用 P99.5 高分位残差。
- 修复：第一级判定 + 共面合并 两处判据都改为残差 P99.5 <= curvatureTol。
- 验证（4工件全回归）：面板单面21行不变（P99.5=2.28）；槽型盘4段67行（凸边轨迹恢复18+21+15+13行）；折型板3段18行；棕色槽型盘4段40行。
- 槽型盘凸起边框是"连通矩形环"（连通域=1，角部相连，4边共面），纯平面RANSAC和连通域都无法拆成4条独立边，需几何拓扑（矩形角点识别）或通用曲面分割才能拆边——待定方案。

- 通用方向（用户原话）："不能只针对槽型盘，要通用，有多少面拆多少面，最好能处理环形/圆柱型"——区域生长+多形状拟合是候选路线，尚未实施。

## 三大修复：阈值语义 + 环形分段 + 空移标记（完成，git 538431c）
- 用户截图"两个大矩形面片重叠歪斜"和"轨迹乱七八糟（梳齿+斜穿线）"暴露三个根因：
  1) **flatnessTol 语义错误**：大 tol(20mm) 被 RANSAC 当内点容差，凸边被吸进底盘平面，最小二乘把平面拉斜（法向从1.000歪到z=0.999/x翻倍），重建面斜穿工件。修正：拟合容差恒紧 tightTol=min(tol,3mm)，flatnessTol 只用作"台阶抹平阈值"——共面片沿法向间距 < max(flatnessTol, curvatureTol*1.2) → 并入主段（保留主平面方程）；否则保持独立。这才是"高度低=完整平面，高度高=分割"的正确实现。
  2) **环形/框形面满铺**：genRows 行端原用包围盒全长，环形面轨迹满铺矩形与底盘重叠。修正：每行按带内点 x 聚类分段（间隙>max(L*1.5,20mm)分段），段长<L 丢弃；行按 segIdx 分组排序（先喷完所有左段行再右段），段间大跳跃直线空移。
  3) **空移当喷涂**：跨段空移被采样成4mm连续点且spray=1，WPF画出斜穿线。修正：空移点 spray=0，WPF RenderTrajectory 遇 spray==0 断开管线并跳过该点。
- 验证（flat=3/curve=5 → flat=20/curve=20）：
  - 面板：单面21行 → 单面 ✓
  - 槽型盘：底盘+凸边57行 → **单面18行**（凸边高差13mm<20被抹平）✓ 符合"阈值20"语义
  - 折型板：底面+翻边95行（翻边30mm>20保持分割）✓
  - 棕色槽型盘：底盘+深槽侧壁 63行 → 40行 ✓；UI实测面片贴合无重叠、轨迹无乱线（44行/1493点，空移148点/喷涂1345点）
- driver.cpp 加 -flat/-curve 参数便于命令行双阈值回归。
- 深槽竖直侧壁的轨迹在侧视角呈梳齿状是正常投影（喷侧壁需竖直面往复），俯视才合理。
